# Issue #764: Warcraft Logs recent-report history ceiling

## Goal and evidence

Three recent character runs stopped with `unavailable` and saved page 6. Replaying the production query on 2026-10-01 returned HTTP 200 plus `The page argument must be a value between 1 and 5.` for each. The scanner follows `has_more_pages` without respecting that ceiling, and the transport turns the validation error into a transient limitation. Public examples and new fixtures are anonymised.

## Proposed fix

1. Add the upstream recentReports maximum page (5) beside the existing page-size constant. Keep page size and GraphQL selection unchanged: changing page size invalidates existing page offsets and changes query complexity.
2. Bound history reads and resume probes to supported pages. Restart any stored cursor beyond the ceiling at page 1 without probing an unsupported page. At the ceiling, report a new `history_limit` limitation if `has_more_pages` is true. A smaller local request cap still reports `request_cap` and supports ordinary resume.
3. Preserve the existing resumed-publication guarantee: a valid cursor above page 1 remains partial if it exhausts history or reaches the scan floor, with `request_cap` and a page-1 restart scheduled for a full scan. Reaching the end or floor licenses complete publication only for a scan starting from page 1. Restarting an unsupported cursor must retain earlier evidence through the first corrected partial publication; it must not mark terminal tiers from a resumed fraction.
4. At the upstream ceiling, emit no out-of-range resume cursor or boundary. Track that history reached its ceiling independently of the driving limitation, so a later retryable failure cannot erase the decision to clear the bookmark. Carry that fact through the provider result and the current-character and historic-alias staging paths, explicitly clearing persisted page and boundary values rather than letting omission carry them forward. No database migration or production writes: existing partial runs reach the corrected path on their next scheduled/ordinary collection.
5. Carry `history_limit` through provider types, contracts, dossier explanation and phase labels. The dossier says Warcraft Logs limits the accessible recent-report history, evidence is partial, and older kills/wipes may exist. Waiting alone cannot extend that history, so `history_limit` alone has no automatic retry. Limited history never licenses terminal-tier marking.
6. Preserve retryable failures at every aggregation seam. In `collect/first-kill.ts`, a ranked-backfill `request_cap`, `unavailable` or `rate_limited` must win over non-retryable `history_limit`, preserving its retry delay and ranked cursor. In `mergeHistoricAliasResponse`, choose the driving limitation with the application retry policy, including both limitation-only and evidence responses; a retryable current or alias failure must win over the other character's history ceiling. Apply the same rule when alias collection is deferred by its budget: its `request_cap` must not be hidden by the current history ceiling. Keep existing parse retry aggregation. Retain the ceiling's separate bookmark-clearing fact when the driving code is replaced, and keep the aggregate publication partial. Equal retry classifications keep the earlier limitation; explicit upstream Retry-After retains precedence. Do not change Raider.IO-only retry policy.
7. Write regressions for fresh scans with five pages still claiming more, natural exhaustion on/before page 5, smaller local request caps, and valid resumes through page 5. Cover valid-cursor exhaustion and floor stops, asserting partial publication, retained earlier kills/wipes/parses, no new terminal tiers, and the scheduled page-1 restart. Cover existing page-6 and greater cursors, including historic-alias progress, asserting that unsupported pages are never requested. Assert cursor and boundary clearing through staging and a real database publication/readback, including a ceiling combined with a retryable driving failure. Test `history_limit` alone with no retry and, separately, retryable ranked-backfill failures, alias failures, deferred aliases and parse failures alongside the ceiling, checking retry deadlines, continuation state and retained evidence. Check the public schema and explanation text with anonymised fixtures.
